Axon Networks XG2010G
*********************

The XG2010G is an optical network terminal based on the Airoha AN7581. This
port is derived from the stock 512 MiB SPI-NAND image and keeps the vendor
flash boundaries intact.

Building
--------

Build the second-stage U-Boot image with an AArch64 cross compiler::

   make xg2010g_defconfig
   make CROSS_COMPILE=aarch64-linux-gnu-

``u-boot.bin`` and ``u-boot.img`` are build inputs, not directly flashable
XG2010G slot images. The vendor first-stage loader requires a packaged slot
image with its FIT at offset ``0x2100``. That packaging step is not provided by
this tree.

Flash layout
------------

The primary layout follows the XR1710G UBI design while retaining the XG2010G
factory-data boundaries:

============ ========== ==========
Partition    Offset     Size
============ ========== ==========
vendor       0x00000000 6 MiB
chainloader  0x00600000 1 MiB
ubi          0x00700000 438 MiB
art          0x1bd00000 3 MiB
reserved_bmt 0x1c000000 64 MiB
============ ========== ==========

``vendor`` contains the stock bootloader, environment and DSD areas. The
``ubi`` partition ends at ``0x1bd00000``, one MiB earlier than the XR1710G 2.0
layout, because XG2010G stores ART data there. Copying the XR1710G end address
would overwrite part of ART.

The original ``bootloader``, ``uenv``, ``dsd``, ``tclinux``,
``tclinux_slave``, ``system``, ``rootfs_data_stock`` and ``reserved_stock``
regions remain available as overlapping read-only compatibility views. They
allow factory-data access and stock boot fallback before UBI is initialized.
Only the primary ``ubi`` view is writable as firmware storage. ART and the
final BMT/BBT area are always read-only.

Boot and recovery
-----------------

The default boot path reads the ``fit`` volume from ``ubi`` and uses the same
``config-1`` convention as XR1710G. If UBI is not formatted or does not contain
a bootable image, U-Boot falls back to the stock ``tclinux_slave`` view. The
stock loader skips bad NAND blocks, reads the FIT header at logical offset
``0x2100``, and loads only the FIT's declared total size.

Holding reset (GPIO 0, active low) during U-Boot startup enters HTTP recovery
at ``http://192.168.255.1``. Firmware recovery accepts an OpenWrt FIT image,
recreates the fixed 438 MiB UBI layout, writes the image to ``ubi:fit`` and
creates ``rootfs_data`` from the remaining space. The erase range is strictly
``0x00700000..0x1bd00000``; DSD, ART and BMT/BBT data remain untouched.

The U-Boot upload target is capped at the 1 MiB ``chainloader`` region starting
at ``0x00600000`` and accepts only a packaged chainloader slot image. Do not
upload a bare FIT, ``u-boot.bin``, or ``u-boot.img``.

Factory data and environment
----------------------------

LAN and WAN MAC addresses are read from the newline-separated key/value data
at the start of the read-only ``dsd`` compatibility view. Other DSD fields are
neither imported nor modified.

The stock ``uenv`` area remains read-only. Persistent U-Boot settings use the
redundant ``ubootenv`` and ``ubootenv2`` UBI volumes, matching XR1710G. Before
UBI is initialized, environment loading falls back to compiled defaults and
``saveenv`` cannot overwrite the stock vendor environment.

Ethernet
--------

U-Boot enables the AN7581 Ethernet block, the internal ``gdm1`` switch path and
the external ``gdm4`` 2.5G recovery path. XG2010G routes its Airoha EN8811H
copper PHY through USB0 Multi-SerDes in fixed-rate HSGMII mode, rather than the
ETH-USXGMII/RTL8261 path used by XR1710G.

The EN8811H uses primary MDIO address 13 with auxiliary addresses 14 and 15.
Its active-low reset is GPIO 31 and is asserted for one second before PHY
initialization. The USB XSI source port is ``0x19`` and recovery TX descriptors
use QDMA channel 12, matching the stock ``hsgmii_lan`` USB path. The EN8811H
MD32 firmware extracted from the stock root filesystem is LZMA-compressed and
embedded in U-Boot so PHY initialization does not depend on a filesystem.

Set ``recovery_port`` to ``2.5g``, ``2g5``, ``2500`` or ``usb`` to force this
port. The existing ``4``, ``10g`` and ``lan1`` aliases still select GDM4 for
compatibility with XR1710G recovery settings.

Hardware status
---------------

The partition map, FIT offset, 1 GiB DRAM size, MAC data format, USB0 HSGMII
register windows and MDIO addresses 13 through 15 were checked against a stock
``XG2010G_fw_1.0.0.13`` dump. The stock environment selects
``serdes_usb1=111`` and the stock preinit sequence resets GPIO 31 for one
second before loading the EN8811H and HSGMII LAN drivers. Serial boot, 2.5G
traffic, reset-button entry and destructive recovery still require validation
on real hardware before deployment.
